# P9.2 已知限制与后续建议

## 1. 真实多角色限制

- 生产库中同一角色 `2124784765` 有 4 条关联行，但 distinct character 仍只有 1
- 因此 `MULTI_CHARACTER_ASSET_SYNC` 只能标记 `PARTIALLY_VERIFIED`
- 双角色隔离、独立同步、独立快照和 IDOR 已由合成测试覆盖
- 后续有第二个真实授权角色后，应执行真实双角色同步验证

## 2. 快照差异真实数据不足

- 当前只有 1 个完整快照
- 第二次同步 hash 相同并去重
- 真实 `real_asset_changes=0`
- 这不是伪造成功：资产确实未变化
- 差异检测类型和双快照对比由合成测试覆盖
- 后续发生真实资产变化后，应复核 ADDED/REMOVED/QTY/MOVED 等真实记录

## 3. 估值费用假设

- 当前估值使用 `ALPHA_DEFAULT_SKILLS` 与 `npc_station`
- API/前端已显式显示该假设
- 未读取角色真实 Accounting/Broker Relations/声望/设施费率
- 因此估值费用是默认假设，不是该角色精确费用
- 后续可读取 `character_skills` 与 standings，按角色生成 `FeeContext`

## 4. 成本基础

- `cost_basis` 永远为 `null`
- 状态：`UNKNOWN_PENDING_P9_3`
- 不能把市场估值当历史购入成本
- P9.3 建立人工真实交易记录与 FIFO 后才能补齐

## 5. 运输与物流

- 本阶段没有完整物流成本引擎
- 跨贸易中心机会运输成本未知时综合利润保持 `UNKNOWN`
- 库存已在 BUY hub 不等于运输已完成
- 后续需要运输路线、合同/燃料、风险和时间模型

## 6. 机会联动库存语义

- `accessible_quantity` 表示本机会实际预留的 BUY hub 可用数量
- 同一 Type + BUY hub 库存按活跃机会优先级只分配一次
- 当前真实结果：0 SUPPORTED、1 PARTIAL、14 UNAVAILABLE、64 NEEDS_PURCHASE
- 若未来需要跨机会可撤回预留、用户手动锁定库存或按计划占用，需要扩展数据模型

## 7. 位置解析边界

- 玩家建筑若没有本地 SDE/ESI 结构元数据，会标记 `ACCESS_RESTRICTED`
- 未知 `location_id` 保持 `UNKNOWN`
- 不通过名称猜测、不把未知建筑当作 Jita/Amarr 等 hub
- 后续可接入 `esi-search.search_structures.v1` 或结构缓存，但需权限与缓存策略

## 8. ESI 数据覆盖

- 公共市场订单无法覆盖所有私有建筑/合同/未公开订单
- 估值中的区域参考和订单簿深度只基于本地已同步 `market_orders`
- 无订单不等于物品无价值，只表示当前没有可用市场证据
- 必须继续显示 `NO_MARKET_DATA/UNKNOWN`

## 9. 测试 flake

- 全量测试两次都出现 `tests/integration/perimeter-radar.test.ts` 时序超时
- 两次单独重跑均为 5/5 PASS
- 该失败与 P9.2 代码无关，但报告中不宣称“单次全量全绿”
- 后续建议降低该集成测试对墙钟时间的依赖或提高隔离度

## 10. 前端包体积

- `web:build` 成功
- 主 JS chunk 约 578 kB，触发 Vite >500 kB 警告
- 不影响功能，但后续可做路由级 code splitting
