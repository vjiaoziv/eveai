# P9.2 安全审计

## 1. 审计范围

- 新增资产服务与路由
- ESI 调用链
- 会话、CSRF、Origin、IDOR
- Token/凭证暴露
- Paper/REAL 隔离
- AI 财务边界
- 真实交易与真实资产写入能力

## 2. ESI GET-only

结论：`ESI_READ_ONLY_PRESERVED = PASS`

证据：

- `src/eve/esi-client.ts` 在 catalog policy 层执行 `evaluateEsiOperationPolicy`
- 最终 `fetchEsiWithRetry` 拒绝非 GET 与非 ESI origin
- `fetchWithTimeout` 同样拒绝非 GET ESI 请求
- P9.2 资产同步只调用 `get_characters_character_id_assets`
- 未新增 ESI POST/PUT/PATCH/DELETE 封装
- `tests/unit/p8-5-6-esi-readonly-gateway.test.ts` 覆盖 UI POST 在认证和网络分发前被 405 拦截

定向安全测试结果：ESI GET-only + Web Security 共 10/10 通过。

## 3. 真实资产写入

结论：`REAL_ASSET_WRITE_DISABLED = PASS`

P9.2 写入只发生在本地 SQLite：

- `real_asset_sync_jobs`
- `character_assets`
- `real_asset_snapshots/items`
- `real_asset_locations`
- `real_asset_changes`
- `real_asset_tags`
- `real_asset_valuations/items`
- `real_asset_opportunity_matches`

不存在：

- 舰船移动
- 物品转移
- 合同创建
- 建筑/市场写入
- 钱包操作
- 任何真实 EVE 资产操作

本地标签、同步记录、快照和估值是 EVEAI 数据，不代表游戏内资产被修改。

## 4. 真实交易执行

结论：`REAL_TRADING_EXECUTION_DISABLED = PASS`

- 未新增下单、撤单、转账、合同、自动交易路由
- 机会联动只计算库存支持关系
- 前端明确显示“不生成真实订单”
- 所有真实交易仍由用户在 EVE 客户端手动执行

## 5. Paper / REAL 隔离

结论：`PAPER_REAL_DATA_ISOLATED = PASS`

- `src/assets/*` 不读取 Paper Trading 库存、资金或订单
- 机会联动只读 `p9_real_opportunities` 与 `character_assets`
- 估值只读快照、SDE、`market_orders`
- 未把 Paper 未成交订单写入真实库存
- 未把真实库存估值写入 Paper 资金

## 6. AI 财务边界

结论：`AI_FINANCIAL_BOUNDARY_PRESERVED = PASS`

- `valuation-service.ts`、`opportunity-match-service.ts`、`history-service.ts` 不调用 OpenAI/Agent
- AI 不修改估值、清算、费用、库存匹配结果
- AI 可以解释结果，但不能覆盖确定性计算

## 7. 会话与 CSRF

新增路由全部使用：

- `requireSession`：读操作无会话返回 401
- `requireMutationSession`：写操作校验 Origin + CSRF，失败返回 403
- 所有响应 `Cache-Control: no-store`

`tests/unit/asset-routes.test.ts` 覆盖：

- 无会话 401
- 缺 Origin/CSRF 的估值 POST 403
- 有效会话可读自己的资产
- 响应不含 `access_token` 或 `refresh_token`

## 8. IDOR

所有角色级接口都通过：

```ts
requireLinkedCharacter(db, session, reply, characterId)
```

只允许当前 `user_id` 已关联角色：

- `403`：请求其他角色
- `404`：物品在本用户所有关联角色中均不存在
- 不确认其他用户角色是否存在
- 快照、估值、库存、变化、联动均做角色归属检查

服务级测试还覆盖双角色数据完全隔离。

## 9. Token 与敏感数据

- Token 只存在 `eve_accounts`
- 新代码/测试不打印 access/refresh token
- 生产验证输出只包含角色 ID、名称、scope 名称和计数
- 报告不包含 Token 值
- 测试使用假 token 字符串，仅用于断言响应不泄漏

## 10. SQL 与输入校验

- 所有用户值使用参数绑定
- 角色 ID、Item ID、分页、日期、枚举均校验
- `bucket/tag/change_type/support_class` 使用白名单或数据库 CHECK
- 不把用户输入拼接进 SQL 列名/表名

## 11. 生产数据库保护

- 迁移前备份：`eve-agent.db.bak_20261103_p92_pre`
- 备份 1,133,785,088 bytes
- 276,803 页，`remainingPages=0`
- 备份 `integrity_check=ok`
- 关键表计数与源库一致
- 迁移前状态记录于 `P9.2-PRE-MIGRATION-STATE.json`
- 迁移创建 9 张新表，不删除历史数据

## 12. 已知安全限制

- 真实环境只有 1 个 distinct character，多角色为合成测试验证
- 未做外部渗透测试；本审计是代码、测试与运行证据审计
- CDP 浏览器自动化的 existing-profile 授权未开启；前端验证改用原生 UIA 只读/点击路径
- 全量测试存在 `perimeter-radar` 时序 flake，单独重跑通过
