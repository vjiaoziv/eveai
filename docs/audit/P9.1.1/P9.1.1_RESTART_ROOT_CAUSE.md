# P9.1.1 重启根因报告

日期：2026-11-03（Asia/Shanghai）
基线提交：`89954d4 feat(p9.1): deliver real ESI market opportunity center`

## 结论（一句话）

**eveai.service 的反复重启不是应用崩溃，而是 WSL 发行版的生命周期绑定 `wsl.exe` 会话：最后一个会话退出后约 20–30 秒，WSL 对发行版执行整机关机（systemd-logind `System is powering down`），eveai.service 被 SIGTERM（退出码 143）；下一条 `wsl` 命令重新启动发行版，`WantedBy=multi-user.target` 的 enabled 单元随之自动拉起。** 交互式高频 `wsl` 调用因此表现为“每 15–40 秒重启一次”。

## 证据（sudo journalctl，2026-11-03 10:20–11:42）

1. **每次停止都是 systemd 发起的关机，不是应用自杀**：
   - `systemd[1]: Stopping eveai.service - EVE AI Agent...`
   - `node[..]: INF app Shutting down...`（应用 SIGTERM 处理器，`src/app.ts`）
   - `systemd[1]: eveai.service: Main process exited, code=exited, status=143/n/a`
   - 同一秒内 `systemd-logind[217]: The system will power off now! / System is powering down.`，同时 cron、rsyslog、snapd、getty 等**全部单元**一起停止 → 整个发行版关机。
2. **计数**：10:20 以来 `status=143` 出现 41 次，`System is powering down` 出现 47 次；每次发行版重启后 systemd 状态全新（`NRestarts=0`、`Result=success`），符合“新 systemd 实例”而非“同一 systemd 内自动重启循环”。
3. **关机触发时机**：与 `wsl.exe` 命令会话结束高度相关——最后一条命令结束后约 20–30 秒关机，下一条命令重新启动发行版。关机前日志有 `WSL CheckConnection getaddrinfo/connect failed` 与 `wsl-pro-service could not connect to Windows Agent`，为 WSL 会话 teardown 的伴生现象。
4. **`.wslconfig`**：`C:\Users\JIAOZI\.wslconfig` 已含 `[wsl2] vmIdleTimeout=-1`，写于 2026-11-01 22:41（早于本次运行），仍发生关机 → 关机由“最后一个会话退出”驱动，而非空闲超时。

## 次生问题：跨发行版重启的运行时锁

11:00:57–11:01:04 连续 3 次：

```text
Fatal error: Database runtime lock names live pid 192, but its process identity cannot be verified.
```

原因：发行版重启后 `data/eve-agent.db.runtime.lock/owner.json` 遗留，新环境中该 pid 被无关进程复用且 `ps lstart` 无法验证 → `process-lock.ts` 按 fail-closed 拒绝启动，阻塞服务恢复。

## 分类判定

- systemd 自动重启：**否**（`NRestarts=0`，无 `Scheduled restart job` 日志）
- 外部进程主动重启：**否**（无脚本/cron/timer；停止序列是整机关机）
- 应用自身崩溃：**否**（143=SIGTERM，来自关机）
- 健康检查触发重启：**否**（无该机制）
- 用户主动重启：**否**
- **真实根因：WSL 发行版随最后会话关机（环境层），叠加跨重启锁残留（代码层）**

## 修复（详见 P9.1.1_REPORT.md）

1. 常驻会话保活：`C:\Users\JIAOZI\eveai-wsl-keepalive.vbs` + HKCU Run 键 `EVEAI_WSL_KeepAlive`（登录自启，隐藏运行 `wsl.exe -d Ubuntu-24.04 -e sleep infinity`）。
2. 锁跨重启回收：`src/runtime/process-lock.ts` 记录发行版启动身份（kernel boot_id + PID1 starttime），上一启动遗留锁直接回收。
3. `Restart=always` 等 systemd 配置**保持不变**（自动恢复机制本身正确，问题不在单元）。
