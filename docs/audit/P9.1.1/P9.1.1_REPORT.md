## 1. 重启根因报告

**根因：eveai.service 跑在 WSL 发行版里，而 WSL 发行版的生命周期绑定 `wsl.exe` 会话——最后一个会话退出后约 20–30 秒，WSL 对发行版整机关机（logind `System is powering down`），systemd 以 SIGTERM 停掉 eveai（退出码 143）；下一条 `wsl` 命令重启发行版，enabled 单元自动拉起。** 高频 `wsl` 调用因此表现为“每 15–40 秒重启”。

证据与排除项（journalctl / unit 配置 / 全盘脚本搜索 / OOM / 端口）详见 `P9.1.1_RESTART_ROOT_CAUSE.md`。要点：

- 10:20–11:42 期间 `status=143` 41 次、`System is powering down` 47 次；每次都是整机关程序列（cron/rsyslog/getty 同时停止）。
- `NRestarts=0`、无 `Scheduled restart job` → 不是 systemd 自动重启循环；无外部 restart 脚本/cron/timer；无 OOM；无看门狗；端口无争用；应用无崩溃。
- 次生问题：发行版重启后遗留运行时锁导致连续 3 次 `Fatal ... process identity cannot be verified` 启动失败。

分类判定：**WSL 环境层整机关机（主因） + 跨重启锁残留（代码层）**；非应用崩溃、非健康检查、非用户手动重启。

## 6. 机会状态变更说明

旧规则：数据新鲜 + 费后净利/ROI 过阈值 → `ACTIONABLE`（导致物流 UNKNOWN 的跨区机会被标为可执行）。
新规则（六属性 + 三段式）：

1. 数据不完整/过期 → `STALE`
2. 低于阈值 → `REJECTED`
3. `tradePlanComplete`（价差 ∧ 订单簿可执行 ∧ 费后利润为正 ∧ 物流已知 ∧ 综合利润可知 ∧ 数据完整 ∧ 数据新鲜）→ `ACTIONABLE`
4. 其余 → `WATCHING`（保留候选、显示费后净利润、综合利润 UNKNOWN、物流待确认）

跨贸易中心在物流成本未知时 `logisticsKnown=false` → 永不 `ACTIONABLE`；站内套利（物流=0 已知）满足全部条件时才 `ACTIONABLE`。详见 `P9.1.1_OPPORTUNITY_STATUS.md`。
