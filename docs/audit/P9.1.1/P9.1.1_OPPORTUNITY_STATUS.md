# P9.1.1 机会状态语义校准

日期：2026-11-03

## 问题

P9.1 中，只要价差通过阈值且数据新鲜，机会即被标为 `ACTIONABLE`。结果：同一批真实数据中 71（后为 75）个**跨贸易中心**机会全部带 `LOGISTICS_UNKNOWN`、综合净利润 `UNKNOWN`，却显示为可执行——把“价差存在”误当成“完整交易条件满足”。

## 新语义：六个独立属性 + 三段式状态

新增属性（类型、DB 列、upsert、映射、前端展示全部落地）：

| 属性 | 含义 |
|---|---|
| `spreadDetected` | 发现价差（买方最优价 > 卖方最优价） |
| `marketExecutable` | 两侧订单簿深度足以支持建议数量（逐档模拟两侧均完整成交） |
| `profitAfterKnownFees` | 扣除**已知**费用后利润为正 |
| `logisticsKnown` | 运输成本已知（站内=0 为已知；跨区=未知） |
| `overallProfitKnown` | 综合（含运输）利润可知 |
| `tradePlanComplete` | 全部必要成本与执行条件已核实 |

状态判定（`stateFor` 重写）：

1. 数据不完整或过期 → `STALE`
2. 费后净利/ROI 低于阈值 → `REJECTED`
3. `tradePlanComplete = true` → `ACTIONABLE`
4. 其余（价差成立、费后有利润，但关键成本未知）→ `WATCHING`

`ACTIONABLE` 现在的充要条件（缺一不可）：
`spreadDetected && marketExecutable && profitAfterKnownFees && logisticsKnown && overallProfitKnown && dataComplete && dataFresh`。

跨贸易中心机会在运输成本未知时 `logisticsKnown=false`、`overallProfitKnown=false`、`tradePlanComplete=false`，因此**永远停留在 WATCHING**，同时保留候选、保留费用后净利润、综合净利润保持 `UNKNOWN`、显示物流待确认——不删除任何真实候选。

## 前端展示（`web/src/components/P9TradingScreen.tsx`）

- 机会列表：状态标签（`WATCHING 观察中` / `ACTIONABLE 完整条件`）+ 五项判定徽章（价差 / 订单簿 / 费后利润 / 物流 / 完整条件）。
- 机会详情：新增 6 属性卡片，以及明确一行：费用后净利润（仅已知费用）/ 运输成本（UNKNOWN 或数值）/ 综合净利润（数值或 UNKNOWN）/ 未知成本说明——**UNKNOWN 不显示为 0**。
- 交易方案表：新增“运输成本”列（跨区=UNKNOWN，站内=0）。
- 总览：区分“完整条件机会”与“观察中（条件未完备）”计数。
