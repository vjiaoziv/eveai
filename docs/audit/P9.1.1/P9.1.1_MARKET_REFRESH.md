## 时间语义（严格区分）

| 概念 | 字段 | 含义 |
|---|---|---|
| 数据采集时间 | `market_snapshot_regions.fetched_at` | 该区域本轮实际从 ESI 拉取完成的时刻（前端“最近采集”列） |
| ESI 数据缓存时间 | `expires_at` | ESI 缓存过期时刻，只决定**何时允许重抓**，不决定行情是否可用（P9.1.1 修正，旧逻辑用它判 STALE 属误判） |
| 快照生成时间 | `market_snapshot_state.snapshot_time` | 全库最老区域的 fetched_at（保守口径；携带的次要层区域未重抓时它保持旧值，侧栏“行情更新于 X 分前”按它计算） |
| 快照完整性 | `pages`/`rows_loaded`/`last_error` + 原子换表 | 换表在单事务内 DROP+RENAME，staging 半成品不会被读到；失败保留旧快照 |
| 数据实际年龄 | `age_minutes` | 当前时间 − fetched_at；超过用户 `maxMarketAgeMinutes` 即 `DATA_STALE` |

## 失败与过期的展示

- 区域抓取失败：`market_snapshot_regions.last_error` 记录，该区域沿用旧行情；前端“ESI 行情与贸易中心状态”表显示错误列，前端状态列按 tier 判 `STALE`。
- 数据超龄：机会打 `DATA_STALE` → 状态 `STALE`；总览“行情整体陈旧”显示“是”。
- 机会有效期：`expires_at = 快照采集时间 + maxMarketAgeMinutes`（与 STALE 判定同一把尺子）；到期由 `P9OpportunityService.expireDue` 置为 `EXPIRED`（修复了旧 SQL 中 ISO `T` 分隔符与 `datetime('now')` 永不相等的比较 bug）。
- 不会为了显示 ONLINE 隐藏过期：`marketSnapshot.stale` 由 tier 判定，`last_error` 直接透出。

## 原子性 / 竞争防护（复用 P9.1 实现，测试覆盖）

- 单飞：cron 与 boot timer 共用 `sweepInFlight`，重入直接跳过。
- staging 表 + 单事务 DROP/RENAME 原子换表；中途失败丢弃 staging、保留 serving 表。
- 运行时锁（`process-lock`）保证同库单写者；P9.1.1 又修复了跨发行版重启后的陈旧锁误伤。
- 覆盖测试：`tests/unit/market-snapshot-loader.test.ts`、`tests/unit/process-lock.test.ts`（全量套件中运行）。
