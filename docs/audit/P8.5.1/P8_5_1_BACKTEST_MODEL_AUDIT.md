## 一、两类回测模式的严格分立

在 EVEAI 回测体系中，必须建立严格的技术隔离：

```text
┌─────────────────────────────────────────────────────────────┐
│                    EVEAI 回测系统架构体系                    │
├──────────────────────────────┬──────────────────────────────┤
│ 1. 日线信号研究回测           │ 2. 历史订单簿执行回测        │
│ (daily_signal_backtest)      │ (historical_orderbook_backtest)│
├──────────────────────────────┼──────────────────────────────┤
│ • 数据源: ESI 每日价格日线   │ • 数据源: 历史逐笔 L2 订单簿 │
│ • 状态: 【当前启用】         │ • 状态: 【数据不足暂未开放】 │
│ • 定位: 宏观趋势与信号筛选   │ • 定位: 微观执行与真实盘口撮合│
│ • 成交性质: 事后均价假设     │ • 成交性质: 逐档真实排队撮合 │
└──────────────────────────────┴──────────────────────────────┘
```

**铁律**: 在未采集到全服按秒记录的真实逐笔 L2 历史订单簿前，严禁启动 `historical_orderbook_backtest`，禁止将日线回测包装为“真实盘口仿真”。

## 二、事后均价假设（Post-Hoc Average Price Assumption）定位

在 `src/trading/backtesting/engine.ts` 中：
- 回测引擎明确将次日均价出场标记为：
  `simulationType: 'daily_signal_backtest'`
  `slippageModel: 'simplified_1.5pct_friction'`
- 明确向用户说明：
  次日均价（$P_{\text{avg}}$）是次日全天全部交易成交后的加权统计值。它反映了该日的市场重心，但并不能保证实盘挂单一定能按此价格 100% 全部出清。
- 收益归类：
  必须在回测结果中明确标为“假设成交收益”（Assumed Execution Return），不得计入“可执行验证收益”。
