# 07 未解决风险与后续验证要求

## 尚未真实环境验证

以下是发布前仍需在受控真实环境中验证的项目：

1. 真实角色 OAuth scopes 与 esi-wallet.read_character_wallet.v1 授权是否完整。
2. 真实 ESI 钱包交易分页的 from_id、X-Pages 和页面稳定性。
3. 请求执行期间由真实另一个连接切换活动角色或解绑角色。
4. 真实钱包交易中的日期、地点、数量、价格和方向格式。
5. 真实交易经人工核实后进入 FIFO 的完整闭环。
6. 真实经纪人费、销售税和其他费用的补录与确定性盈亏。
7. 多角色、多聊天、多用户和多进程并发下的同步状态、租约和游标表现。
8. 真实 ESI 资产分页、角色重绑和陈旧任务 fencing。

## 钱包失败记录的剩余限制

- 持久失败记录表 real_esi_transaction_failures 会阻止游标越过未解决的 transaction_id，畸形行也会通过无 transaction_id 的失败键阻止推进。
- 当前没有独立的“人工隔离已确认不可修复”路由或 UI；长期不可修复的畸形历史记录需要后续设计明确的隔离与审计流程。
- 同一错误批次持续重试会更新 last_failed_at 并递增 retry_count；交易、证据和关联本身保持幂等，但同步尝试会增加运维观测噪音。
- 多进程租约有 TTL 和 owner 检查；真实主机暂停、时钟漂移和进程崩溃后的恢复时间仍需真实环境观测。

## FIFO 与费用完整性

- ESI wallet transactions 不提供完整经纪人费或税费，feeStatus 维持 UNKNOWN。
- 已实现盈亏可能方向、数量、成交价确定，但费用口径尚未完整。
- 当前不自动频繁重算；账本变化后只标记 STALE，等待用户触发重算。
- 真实环境的费用补录、人工核实和确定性盈亏闭环尚未执行。

## 新鲜度时间风险

- 新写入的 P9.3 交易和事件使用带毫秒的 ISO 时间。
- 既有历史数据和部分旧表可能保留 SQLite datetime('now') 的秒级时间。
- 极端同秒变更、时钟回拨或多主机时钟漂移仍需真实环境监控。
- 当前新鲜度依赖数据库时间字符串解析，不依赖生产服务器与 ESI 时间同步。

## 测试覆盖限制

- 真实 ESI、真实 OAuth token 失效、真实跨主机 SQLite 锁竞争未测试。
- 浏览器只执行 TypeScript 检查和生产构建，未做视觉回归或真实浏览器交互测试。
- Vite 主 bundle 为 741.43 kB，超过 500 kB 建议阈值；本阶段未扩大范围处理性能告警。
- 完整套件通过不等于真实生产数据质量通过。

## 状态保持

- 可以维持：P9_3_3_CODE_HARDENED
- 可以维持：REAL_ACCOUNTING_READY
- 不可声明：REAL_ACCOUNTING_OPERATIONALLY_VERIFIED

只有真实账号、真实钱包数据、人工核实、FIFO 和盈亏闭环经过实际验证后，才可讨论运营级验证。
