# 问题清单、修复与验证

## 1. 分级原则

- P0：真实账本污染、数据丢失、认证绕过、跨用户泄露、RCE、生产不可启动。
- P1：核心功能不可用、REAL/PAPER 混淆、FIFO/PnL 错误、严重权限或 CSRF 问题。
- P2：明显影响使用的功能缺陷、稳定性、错误状态或重要视觉/可访问性问题。
- P3：文案、细节样式、低风险性能和维护性问题。

本轮没有确认到 P0 问题；以下为确认并修复的 P1/P2/P3 项。**已通过代码验证**。

## 2. P1 财务与安全边界

| 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|
| 草稿可直接核实交易 | 核实路径没有强制要求非草稿事实和匹配证据 | `p9-3-ledger-service.ts` 增加核实门禁；数据库触发器拒绝草稿直升级 | **已通过隔离测试数据验证** |
| 已核实交易可被无痕降级或删除 | 缺少记录状态不可逆约束 | 增加 `verified_no_downgrade`、`no_delete`、事实不可覆盖触发器 | **已通过隔离测试数据验证** |
| 同一 ESI 证据可关联多条交易 | 证据关系只做外键校验，没有来源唯一性约束 | 服务层与触发器限制单条 ESI 证据只支持一条交易 | **已通过隔离测试数据验证** |
| 费用调整被错误核实 | `FEE_ADJUSTMENT` 缺少失败关闭口径 | 禁止无具体交易归属的费用调整进入核实状态 | **已通过隔离测试数据验证** |
| 部分卖出后 FIFO 成本膨胀 | 成本调整只改批次数量，未同步 `remaining_cost` | 更新剩余成本并按消耗比例分摊；增加剩余数量/成本边界检查 | **已通过隔离测试数据验证** |
| 旧资产快照与后续已核实交易混用 | 资产对账没有校验快照时点 | 对旧快照和后续已核实事实组合失败关闭 | **已通过隔离测试数据验证** |
| REAL/PAPER 可能混算 | Paper 路由/统计可能复用 REAL 默认账户或 actor | Paper 读接口不自动建账户，角色和统计口径分离 | **已通过隔离测试数据验证** |
| AI/system/scheduler 写 REAL 账本 | 写入 actor 校验不完整 | REAL 账本仅接受人工 `user:<id>`；AI `set_autopilot=true` 阻断 | **已通过隔离测试数据验证** |
| ESI 读取路径可能发出非 GET 请求 | 调用方可能绕过最终网关 | 在最终派发网关强制 GET-only，覆盖实际网络路径 | **已通过隔离测试数据验证** |
| 分页参数可被负数、NaN、Infinity 污染查询 | 查询边界未统一校验 | 新增 `src/util/query-bounds.ts`；REAL 对账默认 200、最大 500 | **已通过隔离测试数据验证** |

## 3. P2 功能与可用性

| 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|
| 最新资产快照与估值快照混在一起展示 | `/api/web/assets/overview` 只返回 `latestValuation`，没有说明绑定的是哪一份快照 | 新增 `valuationFreshness`：`CURRENT/STALE/NO_VALUATION/NO_LATEST_SNAPSHOT`，返回最新快照 ID、估值快照 ID、估值物品数和当前物品数 | **已通过真实环境验证** |
| 旧估值警告把旧快照数字当作当前库存总值 | 前端指标文案没有限定“估值快照” | 指标改为“市场参考估值（估值快照）”“买单深度可执行估值（估值快照）”“估值快照未知物品”，并在总览/估值标签页显示警告 | **已通过真实环境验证**，生产页面已显示 `STALE` 警告且无重复标点 |
| P9.3 移动端标签和宽表不可用 | 标签容器不滚动、表格溢出页面 | 标签容器 `overflow-x:auto`；表格加入 `.data-table-wrap`；资产标题改为可换行布局 | **已通过真实环境验证**：390px 下 P9.3 标签 `clientWidth=345`、`scrollWidth=485`，页面无横向溢出 |
| 市场 AI 5xx/429 错误不友好 | 错误分支直接透传通用信息 | 增加中/英/俄本地化提示和未知错误回退 | **已通过隔离测试数据验证** |
| 资产标题在窄屏被挤压 | 顶栏 flex 布局没有移动断点 | 调整 `.asset-screen__topbar` 响应式规则 | **已通过真实环境验证** |

## 4. P3 测试、视觉与维护性

| 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|
| `perimeter-radar.test.ts` 间歇失败 | 测试在假时钟推进后立即读取真实 SSE socket，测试 I/O 时序竞争 | 等待首次成功轮询，并等待真实 I/O 完成；保留业务断言，不跳过测试 | **已通过隔离测试数据验证**：修复后连续 10/10 次完整文件运行通过 |
| 移动端触控目标偏小 | 部分按钮高度约 30–38px、语言按钮约 22px | 记录为 P3，不贸然放大布局；后续统一提升到 ≥44px | **已通过真实环境验证**（问题仍存在） |
| 单 JS chunk 过大 | 当前 Vite 单入口打包，主 chunk `608.20 kB`、gzip `172.13 kB` | 记录为性能风险，未在本轮引入动态拆包重构 | **已通过真实环境验证**（构建警告仍存在） |
| 依赖审计风险 | 初始 `npm audit --omit=dev` 发现 1 high、7 moderate、1 low | 升级 Fastify、`@fastify/static`、`@fastify/cookie`、discord.js、jose、undici、glob 等直接/间接依赖；未使用 `--force` | **已通过真实环境验证**：最终 `npm audit --omit=dev` 为 0 vulnerabilities |
