# 前端可用性、响应式与可访问性报告

## 1. 页面覆盖

**已通过真实环境验证**

使用现有真实认证会话和实际生产页面完成只读浏览：

- 登录页：桌面和移动端。
- 聊天首页、聊天进行中、工具/Agent 状态、数据停靠栏。
- 市场空状态、订单簿、分析、关注列表、AI 搜索错误状态。
- 资产库存、角色资产、库存列表、详情、变化、估值和机会匹配。
- REAL 交易工作台及 P9.3 七个标签：交易总览、交易记录、库存成本、盈亏分析、资产对账、证据中心、审计中心。
- PAPER TRADING。
- PERIMETER 态势感知。
- 飞行员档案六个标签。
- 功能范例、偏好设置、支持与开销。

未执行任何真实交易、自动下单、撤单、转账或资产写入。

## 2. 实际视觉与响应式结果

**已通过真实环境验证**

- 桌面 `1440×900`：侧栏、顶栏、主内容区和 P9.3 审计表格正常；无页面横向溢出。
- 平板 `1024×768`：主内容宽 774px；无页面横向溢出；P9.3 标签容器可滚动。
- 移动端 `390×844`：页面 `scrollWidth=390`，无横向溢出；资产标题高度约 21px，不再被挤压。
- P9.3 移动端子标签：`clientWidth=345`、`scrollWidth=485`、`overflowX=auto`，七个标签可横向滚动，最右侧“审计中心”可点击到达。
- 旧估值警告在真实资产页显示为 `STALE`，文案已经限定为“估值快照”，没有把旧估值与当前 513 行库存混在一起。
- 审计中心 JSON 差异字段可换行，长字符串不会撑破整页。
- 设计系统与实际页面一致：深空背景、玻璃卡片、切角/括号、Exo 2/IBM Plex 字体、青色交互、琥珀色警示和状态色均已使用。

## 3. 可访问性

**已通过代码验证**

- 主要页面使用语义化 `section`、`header`、`h1/h2`、`table`、`button` 和 ARIA role。
- 关键状态提示使用 `role=alert`、`role=status`、`aria-live`。
- P9.3 标签使用 `aria-selected` 和可键盘聚焦按钮。
- CSS 存在 `prefers-reduced-motion` 分支。
- 图标按钮有 `aria-label`，表格具备列标题。

**尚未验证**

- 未逐一完成所有页面的完整键盘 Tab 顺序、焦点陷阱、屏幕阅读器朗读和自动对比度扫描。
- 当前没有自动化视觉回归或 axe 基线；本轮是实际浏览器人工检查，不是完整 WCAG 认证。

## 4. 已确认的 P3 可用性问题

**已通过真实环境验证**

- 移动端侧栏按钮高度约 30–38px，关闭/打开菜单按钮约 36px，删除按钮约 30px，低于推荐的 44px 触控目标。
- 语言切换控件约 22px，未达到移动触控建议尺寸。
- 这些问题不阻断核心流程，但会增加误触概率，列为后续统一样式修复项。

## 5. 性能观察

**已通过真实环境验证**

- 最终构建成功，主 JS chunk `608.20 kB`，gzip `172.13 kB`；Vite 发出单 chunk 超过 500 kB 的警告。
- CSS `129.68 kB`，gzip `20.88 kB`。
- 字体按 Exo 2 和 IBM Plex 子集拆分，当前有多份 woff2。
- 当前为单入口 bundle，尚未做路由级代码拆分；这是性能优化项，不是构建失败。
- 没有在生产上执行负载测试或低端移动设备 CPU 节流测试，因此不能给出 Core Web Vitals 结论。
